# 真实实验、数据分析与迭代记录

所有数值都是本工程假设的**游戏式模拟指标**；没有现实医学或心理学预测意义。已在 Python 3.13 环境运行并记录原始文件。输入 JSON、实验代码和结果均随包附带，便于独立复核。

## 1. 运行方法

```bash
python -m unittest discover -s tests -v
python scripts/benchmark.py
python scripts/stress.py
```

基准采用固定场景、固定算法、无外部 LLM 的可复现运行；采样间隔为一模拟小时。数据库包含全部审计事件，CSV 包含真实小时快照，`summary.json` 是这些运行的汇总。

## 2. 最终数据摘要

| 场景 | 时长 | 行动完成 | 绘画/阅读练习 | 社交成功 | 行动失败 | 行动中断 | 最低 vitality |
|---|---:|---:|---:|---:|---:|---:|---:|
| 可持续单人公寓 | 30 天 | 174 | 59 | 0 | 0 | 0 | 95.00 |
| 资源短缺公寓 | 7 天 | 9 | 3 | 0 | 7 | 0 | 0.00 |
| 中途行动受阻 | 3 天 | 15 | 4 | 0 | 0 | 1 | 2.22 |
| 外部消息干预 | 3 天 | 17 | 6 | 0 | 0 | 0 | 95.00 |
| 双人物共享公寓 | 30 天 | 345 | 118 | 29 | 0 | 0 | 95.00 |

`action_completed` 记录设施和练习完成，不包含单独记录的 `actor_moved`、`social_interaction` 等事件。因此，不能简单把表中计数相加当作总行动数。

在可持续单人公寓中，角色绘画技能从 **4.0** 增长至 **49.1997**，通过真实行动完成了技能目标 40，承诺也完成一次。最大小时采样需求分别约为：口渴 59.66、饥饿 57.42、睡眠压力 75.70、疲劳 48.10。角色未因长期资源不足陷入行动阻断。

双人物世界中，两人共完成 **118** 次练习、**29** 次社交；绘画技能达到 **47.9790**，阅读技能达到 **48.5893**；双方均完成各自长期技能目标。最终双向信任约为 **0.7514**，不是 1.0。这里的信任值是可解释的人工抽象指标，不代表真实友谊的量化。

资源短缺场景中出现 7 次设施使用失败，最终 vitality 到达 0。这是世界没有足够供给、自然需求仍增长的直接结果；当前系统没有尝试凭空补充物资，也不将这一结果视为心理疾病或真实生理预测。仅有 1 条 `action_blocked`，说明延时重试和阻断去重抑制了重复日志风暴。

## 3. 实际开发过程中发现、修复的问题

### 迭代 A：模型与世界输入

第一版后继工程保留 `ActionIntent` + `WorldRuntime` 的因果模式，新增普通练习、社交和长期目标。72 小时、30 天运行验证成功，并产生新的 CSV 与 SQLite 数据。一次初期运行因 `log()` 参数名 `kind` 与日志详情字段重名抛出 `TypeError`；调整明细键为 `commitment_kind` 后恢复。该错误通过实际执行而非静态阅读发现。

### 迭代 B：地图知识与可达性

原有规划器将整个世界地图连接传入路径搜索，虽然限制地点集合，但可能间接利用尚未观察过的连边。更改为 `life.known_edges`，只在当前地点观察后写入邻接关系。第一次回归运行出现未知节点 KeyError，改成 `connections.get(loc,{})` 后测试恢复。30 天生活数据保持稳定。

### 迭代 C：中途打断

首次中断基准设置在角色空闲的 t=670，未能覆盖真正的动作打断；日志中没有 `action_interrupted`。通过审计 `action_started` 的时间区间，改为 t=550，恰好落在 t=494~584 的绘画练习之间。重跑产生 1 条 `action_interrupted`，且不结算原计划的练习收益。新增相关单元测试，验证过期完成事件被 ticket 抑制。

### 迭代 D：多人动作占用

早期 30 天双人物实验，**28 次社交，2 次社交失败**，原因都是 `target_left`：因为发起交谈的一方在忙碌，另一方却可能被调度离开。新增 `ActionPlan.participants`，引擎统一占用/释放双方，允许任一方打断整项活动。**重跑：29 次成功社交，0 次社交失败**。这是机制性的修复，不是直接过滤错误日志。

### 迭代 E：信任值极端化

29 次社交后关系信任曾达到 1.0。进一步检查事件，社交积极/不愉快的比例为 25/4，旧规则线性叠加导致长期数值过快饱和。引入依照当前信任水平减弱单次更新的规则，维持 29 次互动，但最终信任下降至 **0.7514**。保留 `nominal_relation_delta` 与 `applied_deltas` 供后续解释，不虚报实际改变。

### 迭代 F：序列化和测试设计

新增设施标签后，数据库 JSON 将 `tuple(tags)` 还原成 `list(tags)`，造成快照载入不一致；在 `LifeState.from_dict()` 统一还原为 tuple 后恢复。另一个测试最初错误地把“运行 600 分钟后世界水库存变化”归因于外部消息，忽略人物正常喝水消耗。更正为与无消息的等价世界对照，区分模型缺陷和测试假设失误。

## 4. 测试与扰动结果

**单元/集成验收：58 项，通过 58 项。** 覆盖状态上下界、资源守恒、已知地图隔离、动作合法性、中断、多人占用、承诺、技能目标、关系、记忆、SQLite 重启、LLM 输出验证/额度/故障回退等。

**固定种子压力实验：30 组 × 每组 7 模拟天，全部通过。** 每组生成 9 个外部扰动（设施启停、行动能力变化、外部消息），比较一次性推进与多段推进的完整快照、事件序列；额外检查资源非负和人物状态范围。在 30 组扰动实验中汇总观察到：

- `action_started` 2868 次，`action_completed` 936 次，`actor_moved` 1664 次。
- `practice_completed` 293 次，`social_interaction` 49 次。
- `action_failed` 210 次，其中不少来自人为安排的设施停用，并不意味着引擎异常。
- `message_received` 67 次，`world_facility_changed` 139 次。

压力测试不等于穷尽状态空间，也不说明人物行为已经具有心理学意义。

## 5. 哪些方面仍缺少数据？

没有真实远程 LLM API 调用成本、网络异常频率、质量评价数据；没有对模型输出语言进行人工盲评。没有数万 NPC 的性能测试，也没有验证复杂经济/物理规律。社会关系和情绪参数尚未通过真实行为数据标定。

下一步最有价值的试验：明确输入一组复杂社交/计划情境，邀请不同评价者盲评人物行为的一致性和自然度；在锁定世界随机种子的情况下切换不同模型，对比回复质量、指令合规率、请求成本和回退率。
