# 当前版本的设计边界

## 角色知道的事情不等于世界事实

World 保存的真实资源库存只能在实际行动结算时使用；`DecisionPolicy` 不接收全部世界库存。Life 的 `beliefs` 只保存曾经知道的设施用途和上次尝试的反馈，可能过时。角色能够得到观察，也可以探索自己知道存在的地点，但还不能学习未知地图拓扑。

```text
真实世界 ──局部 observe──> Observation ──remember──> Belief
                                                     │
                                              Goal / Decision
                                                     │
                                               ActionIntent
                                                     │
World 验证与结算 <─────────────────────────────────────┘
        │
        └── 实际结果反馈给 Life（last_result、冷却、状态变化）
```

## Goal 与 Action 不同

- `goal='thirst'`：希望缓解口渴；失败后仍然保留。
- `busy={'kind':'move',...}`：已经开始的一段移动；到时间才真正完成。
- 如果目标没有可用方案，则探索尚未到过的已知地点；探索仍失败则等待，定时重试。
- 很紧急的新需求可以打断旧目标，但当前**没有通用 GOAP 规划器**。

## Body 是抽象行动能力模型

`BodySpec` 定义 `vitality` 初始值、空闲恢复、移动/使用设施的消耗、休息恢复、危险需求造成的持续损耗，以及移动/使用门槛。每分钟按固定规则积分，确保分段模拟与一次运行一致。数值不是医学指标；该版本没有真正疾病、损伤部位、生命终止与医学救援模型。

## NPC 与 World 事件

NPC 也只是一个 `LifeState + Persona`，被同一事件引擎调度。当前仅有一个小型 `assist` 行为：**发现同地点低 vitality 的实体后，经过一定时间改变目标 vitality**。不含对话、计划、社会关系，也不保证救助一定发生。

World 可以预先安排 `resource_add`、`facility_disable`、`facility_enable` 和 `vitality_change`。`resource_add.repeat_every_minutes` 可以让世界在无人参与时持续生产资源。它们都是明确的规则/事件，不是角色主观描述。

## 本版不具备的能力

- 不支持真实 QQ/NoneBot、LLM 与外部 API 的副作用。`actor_view()` 是只读数据出口。
- 不支持完整动态地图、物品所有权、装备、复杂容量与设施预留。
- 不支持复杂动作前置条件、行为中断、真实意图预测和通用规划。
- 不支持完整主观世界认知、事件记忆、人物关系、情绪和人格。
- 不支持复杂事件概率生成、完整 NPC 日程和自发社会交互。
- 生理/心理数值只是一种可审计的玩具模型，不能外推现实规律。
- 现有全局资源库存只是一个简化的抽象仓库，非真实所有权系统。

## 重要工程限制

1. **世界是单线程、确定性运行**。对同一分钟事件采用固定优先级；生产模拟需要额外并发/幂等防护。
2. **没有后台服务**。`cli.py` 执行完指定小时数后退出，不会永远运行。
3. **当前是检查点 + 审计日志，不是完整 Event Sourcing**。不能仅凭 `events` 从零重建每一个状态。
4. **场景配置和演化代码更改后应重新开档**。配置指纹包含默认规则版本；自定义扩展逻辑的版本管理仍由调用方负责。
5. **有意保留资源不足导致的危机**。当世界长期不提供水或修复条件，Life 可能陷入无法自主行动；这是世界约束的结果，不是自动恢复失败。
