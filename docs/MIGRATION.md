# 版本升级与存档兼容

## 当前规则版本

`simlife/config.py` 中 `RULESET = "worldlife-next-2.0"`，参与计算场景 SHA256。 v1.0 或 v0.5 的旧检查点**不能不经迁移直接载入**。

## 推荐方法

1. 停止旧服务，使用旧版 `SQLiteStore.backup` 或 SQLite 官方 `backup` API 保存完整数据库。
2. 保留旧程序、旧场景、旧 `.db`，不要直接在上面覆盖测试新规则。
3. 复制世界、人格、场景 JSON，按新版字段和校验要求检查；尤其是地图连通、人物知识、行动标签、项目步骤。
4. 使用**新的数据库文件**启动新版模拟。若需要沿用人物历史，制定逐字段转换程序并对照行为日志人工审核。
5. 分别运行旧版、新版同场景短期基准，检查需求、资源、事件顺序和技能变化是否符合期望。
6. 等到新库运行稳定后再切换适配器；保留旧库作为回滚证据。

## v2.0 新增结构（相较 v1.0）

- `LifeState.projects`：多步骤项目，含 `steps/index/status/retry_at/evidence`。
- `LifeState.propositions`：带来源/置信度/证据历史的主观信念。
- SQLite `checkpoint.revision`：乐观并发版本；`requests`：幂等回执。
- 引擎新事件 `knowledge_signal`；新增服务 API 与自动时钟。

旧数据库中如缺少 `checkpoint.revision` 列，`SQLiteStore` 会添加该列，但这**只是数据库结构补全，不等于世界规则迁移**，存档指纹仍然不同。

**不提供自动转换旧事件日志生成新世界的工具**：旧审计日志可能不包含重建全部状态所需的随机数、模型结果和自定义动作副作用。保留旧档比假装能够无损迁移更安全。
